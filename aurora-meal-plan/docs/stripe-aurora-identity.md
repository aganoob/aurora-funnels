# Stripe ↔ Aurora funnel-session contract

Aurora correlates Stripe activity to a funnel visitor through the opaque `funnel_session_id` generated by the funnel. The funnel does not send an Aurora user ID because Aurora has no such identifier at checkout creation.

## Checkout contract

The funnel creates subscription Checkout Sessions with:

```ts
await stripe.checkout.sessions.create({
  mode: "subscription",
  client_reference_id: input.sessionId,
  metadata: {
    acquisition_platform: "custom_funnel",
    funnel_session_id: input.sessionId,
    funnel_id: input.funnelId,
    product_id: input.productId,
    // Existing Shipflow checkout metadata, including offer_id.
  },
  subscription_data: {
    metadata: {
      acquisition_platform: "custom_funnel",
      funnel_session_id: input.sessionId,
    },
  },
});
```

`client_reference_id` and `funnel_session_id` carry the same funnel-session value. The former is available directly on Checkout Session webhooks; the latter is available in metadata.

## Webhook lookup rules

| Event family | Fields Aurora reads |
| --- | --- |
| `checkout.session.*` | `client_reference_id`, then `metadata.funnel_session_id`; use `metadata.funnel_id` and `metadata.product_id` as acquisition context. |
| `customer.subscription.*` | `metadata.funnel_session_id` and `metadata.acquisition_platform`. |
| `invoice.*` | Subscription metadata snapshot, including `funnel_session_id` and `acquisition_platform`. |

Stripe metadata remains on the object where it is written. Checkout Session metadata therefore carries full acquisition context for checkout events, while Subscription metadata carries the durable funnel-session correlation for recurring subscription and invoice events.

## Operational requirements

- Verify each webhook against its endpoint-specific signing secret using the raw request body.
- Make handling idempotent on `event.id`; Stripe retries events and can deliver duplicates.
- Pin and test the webhook endpoint's Stripe API version because invoice metadata field locations vary across Stripe API versions.
